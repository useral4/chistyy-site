# Kinava Pro

MVP сервиса для быстрой проверки сайта на юридические риски, потенциальные штрафы и SEO-проблемы.

## Что умеет

- Принимает URL сайта и серверно загружает HTML.
- Проверяет документы и штрафные риски: политику ПДн, согласия у форм, cookie, рекламу/ERID, реквизиты, оферту, уведомление оператора, детские данные и платёжные условия.
- Проверяет SEO и техническую базу: title, description, H1/H2, alt, canonical, Open Graph, robots.txt, sitemap.xml, скорость, viewport, Schema.org, favicon и HTTPS.
- Считает ориентировочную верхнюю границу потенциальных штрафов.
- Разделяет проверку на два входа: юридические риски и SEO.
- Показывает понятный отчёт с коротким объяснением «что видно» и «что сделать».
- Закрывает последние 10 пунктов расширенной диагностики до оплаты 179 ₽.
- Ведёт на консультацию с низким порогом входа, а пакеты показывает как ориентир после разбора.

Важно: расчёт штрафов является продуктовой оценкой риска, а не юридическим заключением. Перед запуском в продакшн матрицу штрафов нужно утвердить с юристом.

## Запуск

Если обычный `node` доступен:

```bash
node server.js
```

Если используется встроенный runtime Codex на Windows:

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" server.js
```

После запуска откройте:

```text
http://localhost:4173
```

## Заявки на расчёт стоимости

Обе кнопки «Узнать точную стоимость» открывают форму с выбранной услугой. Обязательны адрес сайта, email и согласие на обработку данных. После подтверждённого сохранения пользователь получает номер заявки и описание следующих шагов. При ошибке поля остаются заполненными.

`POST /api/requests` сохраняет каждую заявку отдельным JSON-файлом в `data/` вне публичной папки. Путь можно задать переменной окружения `LEADS_DIR`. При размещении используйте постоянный диск и ограничьте доступ к этой папке сотрудниками, которые обрабатывают заявки. Каталог исключён из Git. Не направляйте `LEADS_DIR` внутрь `public/`.

Заявки пока обрабатываются вручную из этой папки: автоматической отправки на email или в CRM нет. Для запуска согласуйте с владельцем способ получения заявок и настройте его на хостинге. Форма не обещает конкретный срок ответа. Email клиента нужен для последующего ответа сотрудника.

Демо-кнопка и обработчик бесплатного открытия отчёта удалены. Платёжная интеграция по-прежнему не подключена: кнопка покупки показывает сообщение о недоступности перехода.

## Запуск на хостинге

Проекту нужен Node.js-хостинг, потому что проверка сайта выполняется на сервере через `/api/audit`.
Подойдут VPS, Render, Railway, Fly.io или аналог с командой запуска:

```bash
npm start
```
