# Настройка KinavaPro

## Что готово

44 проверки: 12 юридических и 32 SEO/технических. Источники: главная страница, до восьми локальных JS-файлов, ссылки на политику, robots.txt и sitemap.xml. JavaScript не исполняется, браузерные Core Web Vitals и размещение базы данных не подтверждаются. Не имитируем проверку реестров, вирусов, WHOIS и позиций поиска.

Бесплатно видны все недостатки и доказательства из проверенной страницы. Полный отчёт за 179 ₽ содержит план исправлений и результаты всех проверок. Сервер не отдаёт рекомендации до подтверждения платежа. Для малого отчёта нет фиксированной высоты и размытых «дополнительных нарушений». При отсутствии недостатков в выбранном разделе предложение покупки скрывается.

Санкции: условный справочный сценарий для юрлица, первое нарушение. Политика — ссылка на КоАП 13.11 ч. 3, до 60 000 ₽; возможная незаконная обработка — 13.11 ч. 1, до 300 000 ₽. Cookie и согласие с одним потенциальным составом не суммируются дважды. Расположение базы и уведомление РКН остаются ручными проверками. Это не итоговый штраф и не доказательство правонарушения. ## ЮKassa: только тест

Shop ID владельца: **1391549**. Перед настройкой проверьте в кабинете, что это идентификатор именно тестового магазина.

В Render: сервис → Environment. Установите:

```text
PUBLIC_URL=https://kinavapro.ru
YOOKASSA_MODE=test
YOOKASSA_SHOP_ID=1391549
YOOKASSA_SECRET_KEY=<секретный ключ тестового магазина>
```

Ключ вводится только в панели сервера и не коммитится. Код принимает только ключи с префиксом `test_` и ответы ЮKassa с `test: true`. Боевой режим здесь отсутствует. ID магазина без ключа не позволяет проверить интеграцию в ЮKassa.

Процесс: аудит → создание заказа с фиксированной серверной ценой → переход на страницу ЮKassa → возврат на сайт → серверный запрос статуса платежа. План открывается только при `succeeded`, `paid=true`, тестовом флаге, совпадении суммы, валюты и номера отчёта. Возврат на сайт и текст браузера сами по себе оплату не подтверждают. Повторное создание использует один ключ идемпотентности. Отмена позволяет повторить попытку. Входящий webhook не нужен для текущего тестового сценария: статус проверяется по API при возврате и кнопкой обновления.

Для проверки используйте тестовые реквизиты из https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing . После успешного теста проверьте открытие и скачивание отчёта, отмену и повторную попытку. Обычная карта не предназначена для тестового магазина. Реальный тест ещё не выполнен без ключа.

## Сервер и размещение

Node.js 24, установка `npm install`, запуск `npm start`. Зависимости также закреплены в `pnpm-lock.yaml`; можно использовать `pnpm install --frozen-lockfile`. Тесты: `npm test`.

Для текущей версии **SpaceWeb «Старт» не подходит**: провайдер пишет, что вебприложение Node.js на виртуальном хостинге запускать нельзя, и рекомендует VDS: https://help.sweb.ru/dopolnitel6noe-po-na-serverah-virtual6nogo-hostinga_1208.html . Почта и FTP в тарифе не заменяют постоянно работающий процесс Node.js.

Практичный старт: российский VPS/VDS, 1–2 vCPU, 2 ГБ RAM, от 10 ГБ диска, Node.js 24, Nginx, TLS, systemd для перезапуска и резервное копирование. Это оценка для ограниченного параллелизма HTML-проверок, не гарантия нагрузки. Для полноценного браузерного аудита позже потребуется больше памяти и отдельные воркеры. Готовое решение SpaceWeb: https://sweb.ru/vds/nodejs/ . Тариф «Старт» можно рассматривать отдельно для почты/статических файлов, но не как единственный сервер этого приложения.

Настройте постоянные каталоги вне `public/`:

```text
LEADS_DIR=/var/lib/kinavapro/leads
REPORTS_DIR=/var/lib/kinavapro/reports
TRUST_PROXY=1
```

`TRUST_PROXY=1` включайте только за доверенным прокси, который перезаписывает X-Forwarded-For. Nginx должен задавать этот заголовок. Каталоги доступны только пользователю процесса. На Render нужен persistent disk: стандартная файловая система не предназначена для сохранения после новых деплоев. Размещение контактов в РФ требует отдельного решения и подтверждения инфраструктуры; страна IP/CDN не доказывает место базы. Не настраивайте рабочий сбор данных россиян на зарубежной базе как будто локализация выполнена.

Резервируйте заявки, настройте срок удаления и доступ сотрудников. Отчёты действуют семь дней; истёкшие файлы нужно удалять по расписанию оператора. Лимиты API: аудит/статус — 10 запросов в минуту на адрес, заявки/создание платежа — 5; не более 6 одновременных аудитов. Служебные и локальные адреса, DNS rebinding, неограниченный размер страниц и редиректы блокируются.

## Почта

Готов SMTP-транспорт. Для включения:

```text
SMTP_HOST=<сервер провайдера почты>
SMTP_PORT=465
SMTP_USER=<служебный ящик>
SMTP_PASSWORD=<пароль приложения/почты>
SMTP_FROM=<служебный ящик>
LEADS_EMAIL=<адрес сотрудника>
```

Для STARTTLS используйте 587; обязательное шифрование включено. Заявка сначала сохраняется в JSON, затем отправляется уведомление сотруднику. После доставки появляется файл `.sent`. При ошибке JSON остаётся в очереди; автоматически повторного отправления пока нет, несентированные заявки нужно отслеживать вручную. Письма клиентам автоматически не отправляются. SMTP без данных провайдера и получателя ещё не проверен. Настройте MX, SPF, DKIM и DMARC у почтового провайдера; не ставьте собственный почтовый сервер на новый VPS только ради нескольких уведомлений.

## Метрика и Вебмастер

Существующий счётчик: `METRIKA_ID=<числовой ID>`. Код загружается только после согласия на аналитику; отказ сохраняется, интерфейс остаётся доступен. Вебвизор выключен, чтобы не записывать содержимое контактных форм. Без ID статистика не собирается. Создание/подключение счётчика в аккаунте Яндекса требует доступа владельца.

Вебмастер: добавьте `https://kinavapro.ru`, выберите подтверждение через meta-тег и установите `YANDEX_VERIFICATION=<код>`. Сервер вставляет тег в HTML. Затем подтвердите права в кабинете и отправьте `https://kinavapro.ru/sitemap.xml`. Настройки не подменяют подтверждение в аккаунте. Инструкция: https://yandex.ru/support/webmaster/ru/service/rights .

Документы privacy/consent/cookies — проект для тестовой версии. Перед рабочим приёмом заявок утвердите оператора, фактическую инфраструктуру, срок хранения и получателей; проект прямо отмечен в текстах и закрыт от индексации.

## SEO-правки сайта

Один H1, содержательный title/description, canonical, robots.txt, XML sitemap, SVG/PNG favicon и touch icon, Open Graph, Twitter Card, WebSite JSON-LD, размеры изображений и lazy ниже первого экрана. `/index.html` перенаправляется 301 на `/`. Страницы возвращённой оплаты получают `X-Robots-Tag: noindex, nofollow` и `Referrer-Policy: no-referrer`, чтобы индивидуальные ссылки отчётов не уходили в поиск/сторонние referrer.

В открытом аудите Gvozd от 03.10.2026 отмечены 6 ошибок/4 рекомендации: короткий title, три H1, favicon, robots.txt, Open Graph, микроразметка и настройки редиректа с index.html. https://gvozd.org/audit/kinavapro.ru?workflow=0ac459e3-42ce-42ee-8946-762add2a46ca . Новый балл Gvozd после публикации ещё не подтверждён. Ограничения «не больше 5 H2» и «не больше 8 H3» не копируются как обязательные SEO-правила: количество зависит от структуры страницы.
